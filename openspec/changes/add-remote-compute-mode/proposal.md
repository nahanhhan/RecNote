# Proposal

## Why

RecNote 目前在手机上持续运行语音识别，实际长时间录音会明显发热。增加电脑远程算力模式，让手机负责采集与保存，电脑复用 Voice2Note 完成识别；音频与转写结果经云盘中转，减少公开电脑接口经 cloudflared 传输大文件的负担，笔记整理仍由用户在手机界面发起。

## What Changes

- 设置页最顶端增加「本地模式 / 远程模式」，默认保留本地模式。远程模式隐藏「本地识别模型」，替换为 ASR 后端 URL、token、保存和连接测试入口；手机的「云端笔记整理」区块在两种模式均保留，配置与使用方式沿用现有行为。
- 每份新录音冻结识别模式与 ASR 连接配置。远程任务不启动手机识别进程、不要求下载模型；手动录音、日程自动录音和音频导入遵循同一识别模式。两种模式的笔记整理均由手机按现有 LLM 配置发起。
- 手机复用约 30 秒的完整 WAV 文件，通过手机上的 OpenList 上传独立云盘任务目录；电脑通过自己本机的 OpenList 主动轮询下载。音频上传队列与现有笔记同步队列分开，后者仍不上传原始音频。
- 手机发送带连接 token、任务标识和云盘相对路径的开始通知。电脑返回每次录音独立的任务 token，结束通知包体仅携带该任务 token。结束后继续接收迟到音频，以最终清单核对全部文件，再完成识别；不自动调用 LLM。
- 手机只提供约 30 秒的大切片，V2N 内部使用已有按句切分算法。电脑将每个大切片的完整转写结果与完成标记回写到开始通知给定路径下的 `.transcripts/`；手机进入录音详情时查询该目录，只接收完整结果，不轮询手机侧的小语句。
- 手机取回完整原稿后，用户点击「整理笔记」仍由 RecNote 直接调用手机保存的云端供应商配置，沿用现有预设、提示词、来源快照、工具调用和笔记保存流程。电脑仅做 ASR，其服务 `config.yaml` 只含识别及必需的服务／OpenList 配置，不保存 LLM 配置、不提供整理接口。
- 照片不进入电脑 ASR 流程；手机仍按既有设置支持图文整理或关闭读图后的本地照片插入，导入音频继续只整理文字。
- 原稿与笔记保存在原录音记录中，继续支持离线阅读、编辑、回听、导出及已有笔记同步。根目录新增 `Vec2Note_todo.md`，记录 Voice2Note 服务改造与协议联调事项。
- 明确断网补传、开始／结束通知重试、两台手机任务隔离、凭据保护、配置改变和进程恢复行为。

## Capabilities

### New Capabilities

- `remote-compute-mode`: 顶部模式切换、远程连接配置、每份记录的模式冻结及远程模式避免本机识别。
- `remote-audio-relay`: 约 30 秒音频、双端 OpenList 云盘中转、滚动与最终清单、独立上传队列及补传。
- `remote-session-control`: 开始／结束通知、连接与任务 token、隔离、重试及可靠收尾。
- `remote-transcript-results`: `.transcripts/` 回写、大切片完成判断、进入详情时查询、原稿保存与编辑保护。
- `remote-note-processing`: 完整远程原稿接入手机既有 LLM 整理，保留供应商、提示词、读图、来源与保存规则。

### Modified Capabilities

- `webdav-note-sync`: 使用远程 ASR 原稿在手机整理完成的笔记继续进入既有笔记同步；原始音频只进入单独的远程中转流程。

## Impact

- RecNote：设置、录音服务、导入服务、启动恢复、数据库迁移、详情与列表状态、笔记保存／导出及 WebDAV 客户端。复用现有 16 kHz 单声道 PCM16 WAV 和约 30 秒持久音频，不复用 15 秒识别临时片段。
- Voice2Note：仅复用现有 `transcribe` 的按句切分，新增长期运行的 ASR 服务、原稿回写与任务隔离；服务入口只执行识别阶段，不能运行现有 CLI 的自动两阶段流水线。本仓库只提供协作备忘录，不实现另一仓库代码。
- 对外新增版本化 ASR 控制协议和云盘目录格式。公开电脑接口不传音频；仅 ASR 原稿从云盘取回，笔记由手机既有流程生成和保存。实际 OpenList 挂载与上传／下载路径必须在真实部署中确认绕开预期 cloudflared 链路。
- 现有手机 LLM 预设、提示词、读图、识别模型和历史资料保留；首版不做电脑 LLM、手机按句识别、识别完成自动整理、账号系统、双向云盘恢复或自动删除云端原始资料。
- 本 change 只产出提案、设计、spec 和任务清单；工程与真机验证分开验收。
